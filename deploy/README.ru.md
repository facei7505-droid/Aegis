# Aegis Щит: от пустого сервера до первого клиента

Один сервер защищает сайты многих клиентов. Клиент меняет DNS на ваш сервер. Caddy выпускает HTTPS-сертификат для его домена, Aegis проверяет каждый запрос по пресету его CMS и пересылает чистые запросы на настоящий сервер сайта. Код сайта и хостинг клиента не меняются.

```
посетитель ─► Caddy (HTTPS) ─► Aegis Edge ─► сервер сайта клиента
                                   ├─ Telegram: тревоги и команды
                                   └─ статистика ─► отчёт за месяц (PDF)
```

## Что понадобится

- **VPS в Казахстане**: ps.kz, hoster.kz или другой. 2 vCPU, 2 ГБ памяти, Ubuntu 24.04, публичный IP.
  - Через защиту идут формы сайтов, то есть персональные данные посетителей. Закон РК «О персональных данных и их защите» (ст. 12) требует хранить их в Казахстане. Поэтому сервер должен быть здесь.
  - В лаборатории Aegis на 2 ядрах пропускает около 750 запросов в секунду. Обычный сайт малого бизнеса делает единицы запросов в секунду, так что одного такого сервера хватит на десятки клиентов.
- **Telegram-бот**: создайте его у @BotFather и сохраните токен.
- **Почта** для Let's Encrypt.

## 1. Сервер (10 минут)

```bash
sudo apt update && sudo apt install -y docker.io docker-compose-v2 git
git clone https://github.com/facei7505-droid/Aegis.git && cd Aegis
cp deploy/.env.example deploy/.env && nano deploy/.env      # ACME_EMAIL=ваша@почта
sudo docker compose -f deploy/docker-compose.yml up -d --build
```

Порты 80 и 443 должны быть открыты в панели хостинга.

## 2. Настройка и Telegram

```bash
alias aegis='sudo docker compose -f deploy/docker-compose.yml exec aegis aegis'
aegis edge init --telegram-token 123456:ABC... --server-ip <IP этого сервера> --contact "@ваш_telegram"
sudo docker compose -f deploy/docker-compose.yml restart aegis
```

Напишите своему боту `/id`: он ответит номером чата. Добавьте этот номер как владельца:

```bash
aegis edge init --owner-chat <номер> && sudo docker compose -f deploy/docker-compose.yml restart aegis
```

Теперь бот отвечает вам на `/help`.

## 3. Подключение клиента

1. **Покажите проблему.** Запустите `aegis check shop.kz --pdf shop.pdf` и отправьте PDF владельцу. Проверка пассивная: только обычные запросы к публичным страницам, разрешение не нужно. Активные тесты делайте только с письменного согласия.
2. **Узнайте IP настоящего сервера сайта**: `dig +short shop.kz` (пока DNS ещё не переключён) или в панели хостинга.
3. **Добавьте сайт:**
   ```bash
   aegis edge add shop.kz --origin 198.51.100.7 --cms wordpress --client "ИП Ромашка" --chat <номер чата клиента>
   ```
   - `--cms` — один из `wordpress`, `bitrix`, `opencart` или `generic`.
   - `www.shop.kz` добавляется сам.
   - Номер чата клиент узнает, написав вашему боту `/id`.
4. **Проверьте origin до смены DNS:**
   ```bash
   aegis edge origin-test shop.kz
   ```
   Нужно увидеть «Можно переключать DNS». Если у сайта самоподписанный сертификат, удалите сайт и добавьте заново с `--no-verify`.
5. **Клиент меняет DNS**: A-записи `@` и `www` указывают на ваш сервер, AAAA удаляются, TTL 300. Команда `add` печатает точные записи.
6. **Проверьте HTTPS**: `curl -I https://shop.kz`. Сертификат выпускается автоматически при первом запросе.
7. **Неделя обучения.**
   - Первые 7 дней атаки записываются и приходят в Telegram с пометкой «режим обучения», но не блокируются. Так клиентский магазин не сломается в первый день.
   - Потом блокировка включается сама.
   - Включить раньше: `aegis edge resume shop.kz` или `/resume shop.kz` в Telegram.

## 4. Каждый день и каждый месяц

- **Тревоги** приходят вам и клиенту. Однотипные атаки сворачиваются в одно сообщение раз в 10 минут.
- **Отчёт за месяц**: `/report shop.kz 2026-11` в Telegram или команда:
  ```bash
  aegis edge report shop.kz --month 2026-11 --output shop-11.pdf
  ```
- **Команды** в Telegram, если что-то сломалось или нужно разблокировать:
  - `/pause shop.kz` — блокировки сразу выключены, атаки продолжают записываться;
  - `/unban 1.2.3.4` — снять блокировку с адреса.

## 5. Если что-то пошло не так

| Что видно | Что делать |
| --- | --- |
| «Сайт временно недоступен» (502) | `aegis edge origin-test shop.kz`. Возможно, хостинг клиента сменил IP: удалите сайт и добавьте заново с новым `--origin`. |
| Что-то на сайте перестало работать | `/pause shop.kz` в Telegram. Код инцидента виден на странице блокировки и в тревоге; найдите его в `logs/shop.kz.incidents.jsonl`. |
| Сертификат не выпускается | DNS ещё не указывает на сервер, или закрыты порты 80/443. Логи: `docker compose -f deploy/docker-compose.yml logs caddy`. |
| В логах сайта IP защиты, а не посетителей | Адрес посетителя передаётся в `X-Forwarded-For` и `X-Real-IP`. Включите доверие этим заголовкам в CMS: в WordPress — плагином для реального IP, в Битриксе — в настройках модуля «Проактивная защита». |
| Нужно срочно отключить защиту совсем | Верните A-записи клиента на IP его сервера: через 5 минут (TTL 300) трафик пойдёт мимо Aegis. |

## Что хранится и сколько

- `logs/<сайт>.incidents.jsonl` — только атаки. Пароли, токены, номера карт, телефоны и e-mail маскируются до записи.
- `stats/<сайт>/<дата>.json` — счётчики по дням.
- Всё старше 90 дней удаляется автоматически (`retention_days` в `settings.json`).
- Тела обычных запросов, ответы сайтов и cookie посетителей не сохраняются.

## Честные ограничения

- **Прямой доступ к origin.** Атакующий, который знает настоящий IP сервера сайта, может обойти защиту и пойти напрямую. На VPS клиента закройте 80/443 для всех, кроме IP Aegis. На общем хостинге так сделать нельзя: просто не публикуйте старый IP.
- **WebSocket не проксируется** — защита отвечает 501. Обычным сайтам на WordPress, Битриксе и OpenCart он не нужен.
- **Пресет WordPress проверен на настоящем WordPress** (2 247 запросов работы админа и посетителей, 0 ложных блокировок). Пресеты Битрикса и OpenCart собраны по документации и публичным разборам атак. Для них неделя обучения особенно важна.
- **Один сервер — одна точка отказа.** Держите TTL DNS 300 и следите за сайтами внешним мониторингом (UptimeRobot и т. п.). При аварии верните DNS клиентов на их серверы.
